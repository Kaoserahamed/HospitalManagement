# Code Review Guidelines

## 1. Goals

- Catch defects and design issues early.
- Share knowledge.
- Maintain consistency and quality.

## 2. Reviewer Checklist

- [ ] Correctness: logic matches intent.
- [ ] Tests: adequate coverage and edge cases.
- [ ] Readability: clear naming and structure.
- [ ] Performance: no obvious regressions.
- [ ] Security: no secrets, PHI, or injection risks.
- [ ] Docs: updated where needed.
- [ ] ADR: added for architectural changes.

## 3. Author Checklist

- [ ] Self-review before requesting.
- [ ] Small, focused PRs.
- [ ] Clear description and linked issue.
- [ ] CI green.

## 4. Turnaround

- First review within 1 business day.
- Resolve comments promptly.
- Use "Approve", "Request changes", or "Comment".

## 5. Conflict Resolution

- Discuss in PR comments.
- Escalate to maintainers if needed.
